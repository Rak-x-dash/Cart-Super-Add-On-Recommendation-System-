# Cart-Super-Add-On-Recommendation-System-
When customers add items to their cart, they often miss discovering complementary items that would enhance their meal experience. A significant opportunity exists to intelligently recommend add-ons that customers are likely to accept increasing Average Order Value while improving the overall experience.

Pipeline
Step	Script	Purpose
1	`01_data_generation.py`	Synthetic users, restaurants, menu items, sessions, CSAO events
2	`02_market_basket_analysis.py`	Apriori algorithm + association rule mining
3	`03_feature_engineering.py`	47 features across 6 groups (user, restaurant, item, cart, temporal, interaction)
4	`04_model_training.py`	LightGBM (primary) + RF/GB ensemble, temporal train/test split
5	`05_inference_api.py`	Flask serving API with cold-start fallback chain
6	`06_ab_testing_framework.py`	Welch's t-test / Z-test statistical framework with Bonferroni correction
7	`07_dashboard.py`	Streamlit dashboard for model + business metrics
Setup
```bash
pip install -r requirements.txt
```
Run the full pipeline
```bash
python 01_data_generation.py
python 02_market_basket_analysis.py
python 03_feature_engineering.py
python 04_model_training.py
python 06_ab_testing_framework.py

# Serve
python 05_inference_api.py
# in another terminal:
curl -X POST http://localhost:5000/recommend \
  -H "Content-Type: application/json" \
  -d '{"user_id": "U000001", "cart_items": [{"category": "main", "price": 220}], "candidates": []}'

# Dashboard
streamlit run 07_dashboard.py
```
Notes
`data/`, `models/`, and `reports/` are generated by the scripts above and
are gitignored — run the pipeline once to populate them locally.
The inference API uses an in-process dict as a Redis stand-in
(`Cache` class in `05_inference_api.py`); swap in a real `redis.Redis`
client for production, the interface is identical.
Market-basket priors (e.g. biryani→raita 86%, tandoor→bread 88%) are
hardcoded in `01_data_generation.py` to seed realistic co-purchase
signal in the synthetic event log.
